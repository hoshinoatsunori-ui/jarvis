## 手順そのものはあっさり

ざっくりこうです。

```bash
pip install -e ".[wake-oww]"
python -c "import openwakeword; openwakeword.utils.download_models()"
```

openWakeWord は pip だけだと動かず、学習済みモデルを別途ダウンロードする必要があります。これは`hey_jarvis` のほかにも timer や weather など、いくつかの既製語彙が同梱されるという作り。

次に`config.yaml` でウェイクワードを切り替えます。

```yaml
wake:
  engine: openwakeword
  options:
    model: hey_jarvis
    threshold: 0.5
```

これで終わり。あとは`jarvis listen` を起動するだけです。

## 「ジャービス」で起きた

英語の`hey_jarvis` モデルで訓練されているはずなのですが、**日本語発音の「ジャービス」で反応しました**。

本家は `/ˈdʒɑːrvɪs/` 寄りの音で、日本語の「ジャービス」は `[dʑaːbisɯ̥]` に近い。母音と子音の近さで通ったのか、学習データが思っていたより寛容だったのか、どちらかだと思います。英語風に「ヘイ・ジャービス」と言う必要があるかと身構えていたので、拍子抜けでした。

誤発火も試した範囲では見ていません。しきい値 0.5 のまま、日常の家庭内の雑音レベルでは静かでした。

## つまずいたのは、マイクのレベル

ここが唯一つまずいたところです。

Phase 0 のときに`jarvis level` でマイクレベルを測って VAD しきい値を `0.0040` にしていました。ところが今日の環境では、ウェイクワードは発火するのに**その直後の発話が VAD に拾われず**、「発話が無かったので待受に戻る」が繰り返される。

```
ウェイクワード検出
発話が無かったので待受に戻る
```

もう一度`jarvis level` を回すと、こうでした。

```
暗騒音 (下位20%): 0.0000
発話   (上位5%) : 0.0041
提案するしきい値: 0.001
```

前回測った 0.0040 は、今の環境では**発話ピークのすぐ下**で、ほとんどの声を取りこぼします。原因はたぶん Windows のオートゲイン調整か、ヘッドセットの付け方が前回と微妙に違うか、ドライバの何かでしょう。環境ごと・時期ごとに測り直すべき、という当たり前の教訓です。

`0.001` に下げたら、ウェイクワードのあとの発話もきちんと拾うようになりました。

ついでに、しきい値を測る前に軽くはまったのが、**ヘッドセットのミュートスイッチ**でした。計測を回したら 10 秒間ずっと 0.0000 で、デバイス自体は認識されているのに音だけ届かない状態になっていました。小さな LED が付いているのを見落としていました。

## 実機で全段つながった

しきい値を直してから、6ターンほど話しかけてみました。全部通ったので、以下はログの抜粋です（声は実際にスピーカーから出ています。これはテキスト字幕）。

```
ウェイクワード検出
認識: 今何時?
< 今は日曜日の夜、9時21分ごろですよ。

ウェイクワード検出
認識: 日本の県は何個ありますか?
< 都道府県は全部で47ですね。
< そのうち「県」は43で、ほかに東京都、北海道、大阪府、京都府があります。

ウェイクワード検出
認識: 私の名前はノリです覚えておいて
< 覚えました、ノリさんですね。
< これからそうお呼びしますね。

ウェイクワード検出
認識: 私の名前は
< ノリさんですよ。
```

**builtin ツールの 3 種類（時刻取得、記憶、呼び出し）が実機で全部通った**ことがここで確認できます。LLM の tool use が実際にツール関数を呼び、その結果を自然言語に戻している。設定ファイル経由で MCP サーバを足せば、同じ経路で家電操作に届くはずです（第4回以降で試します）。

## 実機で見えた2つの小さな挙動

### 1. 会話履歴が効くと、こちらの軽い矛盾に気付いてくる

5ターン目で、何気なく「ジャービス、おはようございます」と言ってみました。返ってきたのはこれ。

```
< おはようございます。
< こちらは今、日曜の夜9時過ぎですが、そちらは朝ですか。
```

さっきの時刻ツールの結果が履歴に残っていて、「夜9時なのに『おはよう』は妙だ」と気付いてきた。設定の `max_history_turns: 12` の範囲でこうなるので、短時間の対話なら前後の整合性は保たれます。

これは S2S（第2回で寄り道した）では弱いところです。S2S は音声パスの中にモデルが固定されていて、こういうツール由来の事実（時刻）を会話履歴に紐づけて推論する設計資産を、こちらから持ち込めない。

### 2. 「私の名前は」で切ると、名前を言う前に終わる

3ターン目、最初は「ジャービス、私の名前は」と言って、少し息を継いでから「ノリです」と言おうとしました。ところが VAD の `silence_ms: 800`（800ミリ秒の無音で発話終了と判定）に引っかかって、**「私の名前は」までで切られました**。

STT に渡ったのは `私の名前は`。LLM はこれを「名前を尋ねられた」と解釈して `recall` ツールを呼び、「お名前はまだ覚えていないんです」と答えました。これはこれで賢い振る舞いなのですが、意図したのとは違う。

一息で「私の名前はノリです覚えておいて」と続けると通りました。VAD のしきい値をもっと甘くする（silence_ms を伸ばす）選択肢もありますが、応答の体感遅延とトレードオフになります。800ms は家庭用としては丁度いい点のように感じました。
